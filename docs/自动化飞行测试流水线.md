# M4：无人值守飞行测试流水线

> 一条命令：`make campaign`。起仿真机 → 自动飞 → 取本次日志 → 跑用例 → 出 HTML 报告。

## 1. 它解决什么问题

M2 的用例回答"这条日志好不好"，但日志从哪来？手工飞有三个老毛病：

- **不可重复**：同参数今天飞 3m 明天飞 2.8m，横向比不了
- **不可归因**：手抖造成的姿态抖动会被当成飞机的问题
- **不可追溯**：飞完没人记得当时的电量、飞行模式、参数版本

M4 把"飞"也自动化了。科目固定参数（起飞 → 定高悬停 N 秒 → 降落），
每次飞行在相同条件下产生一条可横向比较的日志。**用例第一次可以面向"回归"工作：
改一个参数 → 重飞 → `make test` → 立刻知道有没有退化。**

## 2. 流水线结构

```
scripts/run_campaign.py（编排器）
 ├─ pytools/sitl.py        PX4 SITL 生命周期：就绪探测 / 日志快照 / 收尸
 ├─ pytools/mission.py     飞行科目：前置检查 / 安全包络 / 遥测订阅缓存
 ├─ pytools/flightdata.py  日志测量（与 M2 共用，口径一致）
 ├─ flytests/              pytest 用例（与 M2 共用）
 └─ pytools/htmlreport.py  单文件 HTML 报告
```

两种模式（这是设计核心）：

| 模式 | 命令 | 用途 |
|---|---|---|
| `live` | `make campaign` | 真飞。证明"这套东西驱动过一架飞机" |
| `replay` | `make campaign-replay` | 不飞，用已有日志跑下游全链路。CI 每次提交都跑 |

**为什么流水线自己也要能回归？** 飞行部分依赖仿真环境，CI 上跑不动；
但测量、用例、报告是纯计算，恰恰是最容易在改代码时弄坏的。
replay 模式让这条链路在任何机器上秒级验证，live 模式留给人跑。

## 3. 安全包络（自动化飞行的底线）

`mission.py` 里的 `SafetyEnvelope` 不是装饰：

- 高度上限（默认 5m，超 1m 容差即强制降落）
- 水平半径上限（15m，起飞后持续算与 Home 点的 haversine 距离）
- 单次飞行时长上限（180s）
- 最低电量（30%，仿真里飞控常不上报电量，此时显式记"跳过"而不是装作通过）

任一越界 → 立即降落 → 记录原因 → 本次活动判 FAIL。
**自动化测试不能以"把飞机飞丢"为代价**，这条在真机测试岗是铁律。

## 4. 首航抓出来的四个真问题

M4 自己就是被流水线的方法论逼出来的——首航当天抓到四个问题，全部修复并留档：

### 4.1 残留符号链接让 SITL 起不来

PX4 启动要建 `rootfs/etc -> build/etc`，链接已存在时它不覆盖，而是
`PX4_ERR` 后直接退出（码 255，只有一行半截报错）。表现为"昨天还能起，今天起不来"。
修复：启动前清理残留链接（`SitlProcess._clear_stale_links`），
同时**只删链接不删 rootfs/fs**（历史日志在那里面）。

### 4.2 stdin=DEVNULL 会把 PX4 拖死

PX4 的 pxh 控制台 poll stdin；stdin 指向 /dev/null 时永远可读（EOF），
它就不停打印 `pxh>` 提示符——实测 5 秒刷 200 万行，直接把读输出的线程拖死。
修复：stdin 必须是保持打开的管道，5 秒输出从 200 万行降到 48 行。

### 4.3 MAVSDK 3.x 的流式 API

`telemetry.health()`、`core.connection_state()` 都是异步生成器，
不能 `await` 取值；反复调用还会持续创建 gRPC 流。
修复：每个 topic 只订阅一次，写入缓存，其余代码只读缓存。

### 4.4 "高度漂移"的口径问题（最有价值的一个）

首航 25s 悬停报了 **0.51m 漂移，超 0.5m 标准仅 2cm**。分桶看曲线：

```
7.4- 9.4s   2.24  (±0.20)   ← 起飞后收敛
9.4-11.4s   2.44  (±0.03)
11.4-13.4s  2.47  (±0.01)
13.4-24.6s  2.49  (±0.005)  ← 稳如磐石
```

不是漂移，是**收敛**：定高控制器需要约 4s 从 2.0m 爬到 2.5m，
旧口径把这段混进了漂移。正确修法不是放宽标准，而是修测量定义——
悬停窗口跳过开头 5s 收敛段（`Thresholds.settle_skip_s`）。
修后同一份日志：漂移 0.51m → **0.05m**，且老日志基线不变、负向验证依然翻转。

> 测试工程师最容易犯的错是"测试不过就改标准"。这里改的是**测量**，
> 标准一字未动——分清这两者，是用例能长期活下去的前提。

## 5. 用法

```bash
pip install -r requirements.txt -r requirements-live.txt

# 完整飞行（需要本机编译好 PX4 SITL，见 sitl-搭建踩坑.md）
make campaign              # 悬停 25s
make campaign HOVER=40

# 只飞 8 秒会发生什么？扣掉爬升/下降后稳定段不足 3s，
# 用例会拒绝判读（SKIP→FAIL），这是设计行为，不是 bug
python scripts/run_campaign.py --live --hover 8

# replay：任何机器、无仿真环境也能跑全链路
make campaign-replay
```

产物在 `campaigns/<时间戳>-<模式>/`：

| 文件 | 说明 |
|---|---|
| `report.html` | 单文件报告，可直接发人 |
| `manifest.json` | 全部结构化结果（报告只是它的视图） |
| `flight.ulg` | 本次飞行日志（含 SHA256 指纹） |
| `junit.xml` / `pytest.log` | 用例原始结果 |
| `sitl.log` | SITL 控制台输出（排障用） |
