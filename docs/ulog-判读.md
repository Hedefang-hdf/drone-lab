# ulog 日志判读：五项指标与一个重要教训

## 一个教训：判读前必须先分段

第一条规则，也是最容易被忽略的：**一条日志里混着起飞、悬停、降落三段，
直接对全程统计会得出完全错误的结论。**

实例：一条 36 秒的日志，包含起飞爬升（0 → 2.5 m）和降落。
如果对全程算"高度漂移"，结果是 2.6 m——看起来严重超标；
但对悬停段单独算，只有 0.04 m。全程油门均值 43%（被地面怠速拉低），
悬停段其实是 48.9%，非常理想。

**先选段（在空中 + 垂直速度近零），再判读。**
`pytools/ulog_report.py` 已经实现了这个逻辑。

## 悬停质量五项判读标准

| 指标 | 判定标准 | 为什么 |
|---|---|---|
| 姿态稳定性 | 悬停段 roll/pitch ±1° 以内 | 正常悬停的姿态扰动量级；超出说明控制回路或振动有问题 |
| 高度保持 | 漂移 < 0.5 m | 定点悬停的典型值；漂移大可能是气压计/光流问题 |
| 悬停油门 | 45%~55% | 理想悬停油门约 50%，留一半余量给抗风与机动 |
| 振动水平 | 角速度峰值 < 30°/s | 排除螺旋桨不平衡、结构松动引起的异常振动 |
| 系统消息 | 无 ERROR | 飞控运行期故障零容忍；WARNING 要逐条看上下文 |

## 数据在飞控里的流向（判读时心里要有这张图）

```
传感器(IMU/气压计/GNSS/磁力计)
        ↓
   EKF 状态估计（融合出 roll/pitch/yaw/位置/速度）
        ↓
   控制器（四环串级 PID）
        ↓
   混控器 Mixer → 电机 PWM
```

判读异常时按这条链路定位：
- 姿态角跳变 → 查传感器原始数据 → EKF innovation
- 高度漂移 → 查气压计原始值 + EKF 高度融合
- 电机输出异常抖动 → 查姿态环输入输出 → 振动

## 工具链

```bash
ulog_info xxx.ulg      # 日志里有哪些 topic、多少样本
ulog_messages xxx.ulg  # 全部系统消息（按级别过滤）
ulog2csv xxx.ulg       # 转 CSV，用 Excel/pandas 分析
python pytools/ulog_report.py xxx.ulg   # 本仓库的体检报告
```

图形化用 PlotJuggler：多曲线叠加，对比同一飞行的输入与输出。
