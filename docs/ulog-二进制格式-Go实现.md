# 用 Go 手写 ULog 解析器：四个必踩的坑

> 目标：不依赖 pyulog / Python 环境，把 `.ulg` 直接解析成结构化数据。
> 产物是一个可执行文件，同事拿到日志双击就能出报告。

## 为什么要自己写

| 方案 | 代价 |
|---|---|
| 调 pyulog 导出 JSON，Go 只做渲染 | 部署时要 Python + venv，单文件分发就没了意义 |
| 纯 Go 解析 | 要读懂二进制协议，但换来零依赖、快、能并发处理多架次 |

实测纯 Go 解析 8.4MB / 94745 条数据消息，**约 0.5 秒**（含判读 + 出 HTML）。

## 文件结构

```
16 字节文件头: "ULog" 0x01 0x12 0x35 (7B) + 版本(1B) + 起始时间戳 µs (8B, LE)
之后是消息流，每条: <长度 uint16 LE><类型 1B><载荷 长度字节>
```

解析器不需要理解全部消息类型，只要**按长度跳过不认识的**就不会迷路。

## 坑 1：格式串是「类型 字段名」，不是「字段名:类型」

真实内容（`F` 消息）：

```
vehicle_attitude:uint64_t timestamp;uint64_t timestamp_sample;float[4] q;...
```

即 `<消息名>:<类型> <字段名>;<类型> <字段名>;...`。

第一次按 `name:type` 去想，会把第一个字段（`timestamp`）丢掉，
后面所有字段整体错位——而数据长度看起来"差不多"，不报错，只算出垃圾。

**教训**：解析二进制格式，先 dump 一条真实样本，别照记忆写。

## 坑 2：`_paddingN` 填充字段不写入数据消息

格式里声明了 `uint8_t[7] _padding0`，但数据消息里**没有这 7 个字节**。
对齐填充只服务于内存布局，不落盘。

证据：`vehicle_attitude` 格式声明宽度 56 字节，实际数据消息只有 49 字节，
差值 7 正好是 padding 的长度。其他主题同样规律（sensor_accel 48 vs 45、
sensor_baro 40 vs 33、ekf2_timestamps 24 vs 22）。

处理：读到 `_` 开头的字段，**跳过且不消费字节**。

## 坑 3：`A` 消息里 msg_id 是文件给的，不能自增

```
A 载荷 = multi_id(1B) + msg_id(2B, LE) + 名称(零结尾)
D 载荷 = msg_id(2B, LE) + 数据
```

早期按「第几个 A 就是第几号」自增，结果数据全串到别的主题上。
真实文件里 msg_id 跳号（0, 1, 110, ...），必须以文件里的为准，按 msg_id 建索引。

## 坑 4：系统消息等级是 ASCII 数字

```
L 载荷 = 等级(1B) + 时间戳(8B, LE) + 正文
```

等级字节是 `'0'`~`'7'`（ASCII 码 0x30~0x37），不是位掩码：

| 字符 | 含义 |
|---|---|
| '0'~'3' | EMERGENCY / ALERT / CRITICAL / **ERROR** |
| '4' | **WARNING** |
| '5'~'6' | NOTICE / INFO |
| '7' | DEBUG |

一开始用 `byte & 0x3F` 去当字符，`0x36` 变成控制字符，看着像乱码；
用 `& 0x0F` 又会把 INFO 认成 ERROR。直接当 ASCII 数字读才对。

顺带：`I`（信息）消息的键名是**长度前缀**的（`key_len(1B) + key`），
不是零结尾——同一个文件里不同消息的字符串编码方式并不统一。

## 交叉验证：两套独立实现必须算出同一组数

Python 侧（pyulog）与 Go 侧（手写解析）对同一份样例日志的判读：

| 指标 | Python | Go |
|---|---|---|
| 日志时长 | 35.8 s | 35.8 s |
| 悬停段 | 20.8 s | 20.8 s |
| 横滚 / 俯仰 | ±0.33° / ±0.35° | ±0.33° / ±0.35° |
| 高度漂移 | 0.04 m（均高 2.50） | 0.04 m（均高 2.50） |
| 悬停油门 | 48.9% / 峰值 49.6% | 48.9% / 峰值 49.6% |
| 角速度峰值 | 2.1 °/s | 2.1 °/s |
| 系统消息 | ERROR 0 / WARNING 1 | ERROR 0 / WARNING 1 |

这些数字被钉进了 `gotools/hover/metrics_test.go`：
任何一边改坏了协议解析，测试立刻红。

> 为什么要"重复实现一遍"？因为单实现的测试只能证明"代码符合我的理解"，
> 双实现一致才能证明"我的理解符合协议"。

## 代码位置

| 文件 | 职责 |
|---|---|
| `gotools/ulog/ulog.go` | 解析器：格式、订阅、数据、消息、信息 |
| `gotools/hover/metrics.go` | 判读：悬停窗口、指标、阈值（与 Python 同口径） |
| `gotools/report/html.go` | 渲染：单文件 HTML + 手写 SVG 曲线（无外部依赖） |
| `gotools/cmd/ulog2html/main.go` | CLI：`ulog2html x.ulg -o out.html`，退出码可串流水线 |

```bash
make ulog2html                 # 编译并给样例日志出报告
make test-go                   # 跑 Go 单测（含交叉验证基线）
```
