## 这两份报告在讲什么

首航（真 SITL，全程无人干预）的判定是 **4 PASS / 1 FAIL**：

```
[FAIL] 高度保持   漂移 0.51 m（均高 2.50 m）  标准 0.5 m 以内
```

只超了 2 厘米。这时候有两条路：

1. **把标准放宽到 0.55 m** —— 结论立刻变绿，但这是测试工程里最典型的反模式（改标准迎合结果）
2. **先问"这个 0.51 是怎么算出来的"** —— 查测量定义

选了第 2 条。把悬停段按 2 秒分桶看高度曲线（悬停窗口 7.4s–24.6s，共 17.2s / 2154 个采样点），形态很清楚：

```
   7.4 -  9.4s   2.237 m  (极差 0.398)   ← 还在定高收敛
   9.4 - 11.4s   2.435 m  (极差 0.069)
  11.4 - 13.4s   2.471 m  (极差 0.017)
  13.4 - 15.4s   2.484 m  (极差 0.010)
  17.4 - 19.4s   2.498 m  (极差 0.004)   ← 稳如磐石
  23.4 - 24.6s   2.500 m  (极差 0.045)   ← 末段开始准备降落

整窗极差 0.512 m  →  跳过前 5s 后 0.047 m
```

**不是漂移，是定高控制器的收敛过程**被算进了"悬停段"。所以修的是测量定义：
`Thresholds.settle_skip_s = 5`，判读前跳过前 5 秒收敛段。

重判结果：**漂移 0.047 m**，标准仍是 0.5 m，一个字没动。

> 面试里被问「测试不过怎么办」，这就是可以讲的答案：
> **先验证测量，再怀疑被测对象，最后才考虑标准。**

## 怎么重新生成

```bash
# 首航那种完整流水线（需要 PX4 SITL）
make campaign

# 不飞，用已有日志重跑「取数 → 测量 → 用例 → 报告」全链路
make campaign-replay ULOG=data/20261027-sitl-hover.ulg

# 指定输入与输出目录
.venv/bin/python scripts/run_campaign.py --replay path/to/flight.ulg --out campaigns/xxx

# Go 版 HTML 报告
make ulog2html
```
